# 安全、回滚与限制

[English](SAFETY.md) · [说明文档](../README.zh-CN.md)

## 信任边界

使用 sudo 前请审阅本地脚本。工具只使用 Apple 系统命令和 Bash，不下载或执行远程代码，不发送遥测。环境变量不能重定向特权操作的偏好域、键、备份目录或系统命令。请勿运行来源不明的修改版，也不要在其他用户能同时篡改脚本的目录中以 root 运行。工具无法防御已经被控制的 root 账户或操作系统。

该偏好未经 Apple 公开。支持 macOS 13+ 的命令工具，不代表每个版本都存在相同配置或具有相同语义。目前只有一个 macOS 27.2 案例验证了真实视频恢复。遇到缺失、未知或格式异常时，工具拒绝写入。

## 写入条件

修复必须同时满足：

- macOS 13+，且有权限读取 root 服务偏好。
- `defaults` 导出中已存在类型明确的布尔值 `false`。
- 没有 DEP/MDM 注册，注册状态能够读取。使用 `LC_ALL=C` 解析英文结果，无法识别的输出会停止修复。
- 受管理的 `com.apple.applicationaccess` 中不存在 `allowCamera=false` 或类型异常；也不存在受管理的 `com.apple.cameracapture` / `com.apple.cmio.registerassistantservice` 文件。与相机无关的屏幕使用时间配置不算相机限制。这只是保守检查，不是完整策略引擎。
- 当前本地图形用户可识别，且没有其他用户持有 ContinuityCaptureAgent。
- 固定系统父目录由 root 持有、组和其他用户不可写；备份和事务目录为 root 所有、权限 `700`、无 ACL 条目。
- 无未完成/无效事务、无并发锁，已明确确认或传入 `--yes`，并已成功校验备份。

确认后会在关键步骤重复检查。但该偏好没有公开的原子比较并交换接口，其他特权进程仍可能在最后检查与写入之间改变它。请避免同时运行其他设置工具。

## 备份格式

`/private/var/db/macos-continuity-camera-fix/YYYYMMDDTHHMMSSZ.XXXXXX/`

| 文件 | 内容 |
| --- | --- |
| `before.plist` | 修改前的 root 偏好域，可能包含私人信息，不应公开 |
| `before.sha256` | 导出文件的 SHA-256，可检测损坏，不是防御 root 篡改的签名 |
| `format` | 当前格式版本为 `1` |
| `status` | `prepared`、`applied`、`recovered`、`recovery-required` 或 `rolled-back` |

受校验文件必须是 root 所有、权限 `600`、仅一个硬链接的普通文件，不允许符号链接或 ACL 条目。状态更新通过受保护目录内的重命名完成。锁目录阻止本工具并发执行。备份长期保留，脚本不提供清空命令。

写入前必须成功校验备份。如果写入失败或无法校验结果，**只有当前值仍是已知布尔值时**才自动尝试恢复。未知状态会停止进一步自动写入并保留记录。SIGINT/SIGTERM 通常能释放锁；写入后发生中断可能保留 `prepared` 状态，可使用回滚处理。事务记录便于恢复，但不是文件系统与偏好服务之间的原子事务，断电和硬件故障仍存在风险。

## 回滚语义

先执行 `bash macos-camera-fix.sh backups`，再执行 `bash macos-camera-fix.sh rollback ID`。

只接受工具固定目录中的有效 ID，不接受任意路径或导入的 plist。工具检查校验和、原始 `false`、元数据、当前类型和事务状态。只写入目标键，不使用 `defaults import`，因此不会用旧快照覆盖其他偏好。

如果当前值已为 `false`，可直接结束事务而无需重复写入。已回滚或已恢复的旧 ID 不会撤销后续修复。当前值未知或非布尔值时拒绝覆盖。但其他工具后来写入的同一个布尔值 `true` 与本工具的写入无法区分，回滚前应检查改动历史。这是冲突检测的已知限制。

回滚不重复修复时的策略/会话门槛：它仅恢复经验证的原始关闭状态，因此环境变化后仍可以撤销此前修复。回滚不会修改策略文件。如果服务缓存了旧值，请正常重启。

## 中断与遗留锁

先阅读输出，不要删除整个备份目录或恢复整个偏好域。

1. 运行 `bash macos-camera-fix.sh backups` 查看事务。
2. 对 `prepared` 或 `recovery-required` 尝试 `rollback ID`；当前值必须仍为有效布尔值。保留 `INVALID` 事务供检查。写入前导出失败也可能留下无效事务，工具会主动阻止后续修复。
3. 如果锁阻止恢复，在本机查看 PID：

   ```sh
   sudo cat /private/var/db/macos-continuity-camera-fix/lock/pid
   ps -p PID -o pid,etime,command
   ```

   将 `PID` 替换为实际数字。若操作仍在运行，请等待完成。PID 可能被复用，必须检查命令。**只有确认没有任何本工具实例在运行后**，才删除遗留锁，不删除备份：

   ```sh
   sudo rm /private/var/db/macos-continuity-camera-fix/lock/pid
   sudo rmdir /private/var/db/macos-continuity-camera-fix/lock
   ```

   崩溃后 PID 文件可能不存在，第一条命令可能报文件不存在。不要强制删除非空锁目录。之后重试 `rollback ID`。

4. 如果仍无法校验或回滚，保留备份、退出码和脱敏摘要，寻求进一步检查。程序特意不提供 `--force` 或“强制修复未知配置”的选项。

脚本不会撤销人工注销、重启、手机信任授权或 Apple 首次使用引导。回滚范围仅限它修改的那一项偏好。

## 隐私

默认检测只输出工具/系统版本、存储开关状态、管理检查结果以及后台相机服务用户数量。不输出用户名、手机名称、设备 UUID、Apple 账户或序列号。

`check --logs` 会将范围明确的最近 10 分钟统一日志读入受保护临时文件，只输出主机禁用、控制台用户不符、设备发布三类标记的数量。不会上传或打印原始内容。正常退出会清理临时文件；SIGKILL 或断电可能在 `/private/var/tmp` 留下权限 `700` 的临时目录。以 root 运行检查/修复/回滚时也使用临时偏好域导出。长期备份会有意保留。

## 退出码

| 代码 | 含义 |
| --- | --- |
| 0 | 检查完成、操作成功、预演完成或无需改动；不证明视频可用 |
| 1 | 操作、备份、验证或恢复失败；请检查输出与事务记录 |
| 2 | 参数错误或系统不支持 |
| 3 | 证据、策略、会话或备份状态不安全/未知，拒绝操作 |
| 4 | 取消确认或无法交互确认 |
| 5 | 存在并发操作或遗留锁 |
| 130 / 143 | 收到中断信号；请检查事务记录 |

在脚本获得特权之前，`sudo` 本身也可能返回认证或授权失败的退出码。
